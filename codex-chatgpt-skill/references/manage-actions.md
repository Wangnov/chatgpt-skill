# ChatGPT 管理操作手册

用户说"删了这个对话"/"把 X 归档"/"看一下我都分享了什么对话"/"清掉我的 Memory" 时按本文档找入口。**任何破坏性操作（删/归档全部/撤销分享）必须先口头跟用户确认，再执行**。

## 1. 对话级管理

### 普通对话（不在项目里）`...` 菜单 7 项

侧栏 hover 对话项 → 右侧出现 `...` → 点开：

```
分享 / 开始群聊 / 重命名 / 移至项目 → / 置顶聊天 / 归档 / 删除（红）
```

### 项目内对话 `...` 菜单 7 项（**跟普通的差 2 项**）

```
分享 / 重命名 / 移至项目 → / 从"<项目名>"移除 / 置顶聊天 / 归档 / 删除（红）
```

差异：
- 项目内**没有"开始群聊"**
- 项目内多了**"从 X 移除"** —— 把对话移出项目变成普通对话（不删数据）
- **项目内对话不能置顶**：点了会报红色 toast "无法置顶项目或 GPT 对话"

### 重命名

inline 编辑模式（不弹窗）。点 `重命名` → 侧栏对话名变成可编辑文本框（原名被全选） → 输入新名 → Return 提交。

### 分享 — ⚠️ **对话级：打开即创建公开 URL**

实测发现：**对话**的"分享"弹窗——只是点开就会在后端创建公开链接，哪怕不点"复制链接"也不发布到社交平台。

分享弹窗：标题 / 对话卡片预览（带 ChatGPT 水印）/ 4 个按钮（**复制链接 / X / LinkedIn / Reddit**）/ "查看者将无法看到记忆来源"。

**主 Codex 必须做的事**：
- 没用户授权前**绝不点"分享"**
- 一旦不小心点了，去 `#settings/DataControls → 管理共享链接` 把对应行删了（撤销公开 URL）
- 撤销共享链接没有二次确认弹窗，点一下就立刻撤销

> **⚠️ 注意：图片的"分享此图片"弹窗行为不同！**实测点开图片分享弹窗**不会**自动创建公开 URL（共享链接列表里不会新增）——只在用户点"复制链接"时才创建。这是个差异，详见第 6.5 节"产物下载 → 图片"。

### 开始群聊（只对普通对话可用）

弹窗："通过此对话开启群聊 — 仅共享此对话。你的个人 ChatGPT 记忆将始终保持私密。" + 取消 / 开始群聊。

点确认估计创建群聊邀请 URL（行为等价于分享）。**视同分享操作处理**——必须用户授权才能点。

### 移至项目 / 从项目移除

- "移至项目 →" 子菜单列所有项目，点目标即移
- "从 X 移除" 只对项目内对话有；把对话从项目踢回普通最近列表，不删数据

### 置顶聊天

普通对话：点了固定在侧栏顶部。
项目内：报错 toast。

### 归档

点了直接归档，无二次确认 + 顶部 toast "你可以在'设置'中查看归档的聊天"。归档后对话从主侧栏**完全消失**（不显示在"已归档"段，必须去设置看）。

### 删除（红，破坏性）

二次确认弹窗：

```
删除聊天？
这会删除"<对话名>"。
访问设置以删除此聊天期间保存的所有记忆。
[取消] [删除]
```

**关键提示**：**删对话不自动清 Memory**——主 Codex 删完后要提醒用户去 `#settings/Personalization → 记忆 [管理]` 单独清理。

**操作易踩的坑**：对话级 `...` 菜单里"删除"是最后一项，且 accessibility tree 里 menuitem 名称有时返回空字符串（不是"删除"二字）。要靠**位置**（菜单最后一项 = 删除）+ **点击后看是否弹"删除聊天？"**确认操作正确。点错前面的菜单项（如"归档"）不会弹任何确认——直接执行。

## 2. 项目级管理

### 创建

侧栏 "新项目" 按钮 → 弹"创建项目"对话框（名称必填、emoji 图标按钮、齿轮按钮、文案说明）→ 点"创建项目" → **自动跳进项目主页**。

### 项目主页

URL 模式：`/g/g-p-<project-uuid>/project` 或带 slug `/g/g-p-<project-uuid>-<name-slug>/project`。

页面结构：
- 项目标题 + 图标
- composer（placeholder = **"<项目名>中的新聊天"** — 这是"在项目里"的可靠视觉信号）
- "聊天 / 来源" tab
- 右上角 "分享" + "..."

### 项目设置（标题右上 `...` → "项目设置"）

弹窗里能改：
- **图标颜色 × 形状**（8 色 × 30+ SVG icon）
- **项目名称**
- **指令**（项目级 system prompt，多行 textarea；**实测注入有效**——回答会带这条指令的语调/规则 + 出 "<项目名> 项目指令 ↗" source 引用）
- **记忆**下拉（UI 有但"此设置无法更改"）
- 底部"删除项目"红色按钮

### 项目知识库（"来源" tab）

- URL: `?tab=sources`
- 列表：所有项目附件（PDF / docx / 等）
- 顶部"+ 添加源"
- 添加源 = 文件上传。Codex Chrome Extension 优先走 file chooser；如果扩展文件权限不足，停下来让用户按 Chrome 扩展提示开启文件 URL 权限

### 项目侧栏 `...` 菜单 3 项

```
分享项目 / 重命名项目 / 删除项目（红）
```

### 删除项目（**双重破坏**）

确认弹窗：

```
删除项目？
这将永久删除所有项目文件和聊天。要保存聊天，请在删除前将其移至聊天列表或其他项目中。
[取消] [删除（红）]
```

主 Codex 必须：
- 提醒用户 **项目内的对话也会一起永久删**
- 如果用户想保留对话，提示先用对话 `...` → "从 X 移除" / "移至别的项目"

## 3. Message 级 `...` 菜单（每条 assistant 回复下方）

hover assistant message 后底部出现 4 个按钮：复制 / 上传 / 重新生成 / `...`。点 `...`：

```
[时间戳]
查看来源 / 新聊天中的分支 / 朗读
```

- **新聊天中的分支** = branch/fork：从这条 message 开始派生新对话，自动命名 "分支 · <父对话名>"。**这是个被低估的功能**——可以保留主线的同时在分叉里试别的方向
- **查看来源** = 看这条 message 的 source citation（@app 引用 / 项目知识库引用 / 网页搜索引用链）
- **朗读** = TTS

**没看到"安排"创建定时任务的入口**——Instant 和 Pro 实测**都没有**（2026-05-25 验证）。`#settings/Schedules` 提示说"从对话中的 ... 菜单中选择 ⏰安排"，但实际 message 级和对话级 ... 都不包含。可能要：(1) 用 prompt 让 ChatGPT 主动建议（"每天 X 点提醒我..."），(2) 走 `/schedules` 全局页面手动建。等真实场景遇到再补完整入口。

## 4. 数据管理面板（`#settings/DataControls`）

| 入口 | URL/路径 | 用途 |
|---|---|---|
| 共享链接管理 | DataControls → 共享链接 [管理] | 看 + 删所有已分享对话的公开 URL（**撤销分享的唯一入口**） |
| 已归档聊天 | `#settings/DataControls/ArchivedChats` | 看归档列表 / 取消归档 / 单删 |
| 归档所有聊天 | DataControls → [全部归档] | 批量归档 |
| 删除所有聊天 | DataControls → [全部删除]（红） | 批量永久删 |
| 导出数据 | DataControls → [导出] | 邮件发完整 zip |
| 训练贡献开关 | DataControls → "为所有用户改进模型" | 是否用用户对话训练 |
| 位置开关 | DataControls → "位置" | 是否给 ChatGPT 用 IP/地理 |
| 远程浏览器数据 | DataControls → "远程浏览器数据" | Atlas 浏览相关 |

### 已归档聊天表格

- 名称 / 创建日期
- 每行右侧两图标：**取消归档**（左）/ **删除**（右）
- 取消归档：把对话恢复到原位置（项目内的回项目，普通的回最近列表）。**UI 列表可能不立刻刷新**——但功能成功

### 共享链接表格

- 名称 / 类型（**聊天 / 帖子**）/ 共享日期
- 类型 "帖子" 是 GPT-Discover 平台的发布，跟"聊天"分享不同
- 每行可"打开" + "删除"

## 5. 个性化面板（`#settings/Personalization`）— ⚠️ 隐私重灾区

### 顶部字段（用户填的画像）

| 字段 | 说明 |
|---|---|
| 昵称 | 用户希望 ChatGPT 怎么称呼自己 |
| 职业 | 自由文本 |
| **你的详情** | 自由文本——**实测见过住址 / 关系等强隐私**。主 Codex **绝不导出**到日志/文件/外部窗口 |
| 基本风格和语调 / 特征调节 | 全局回复风格 |
| 自定义指令 | 全局 system prompt（项目指令优先级更高） |
| 关于你 | 略 |

### 记忆 [管理]

弹"保存的记忆"列表：
- 搜索框 + 排序 + `...`（推测有"全部清空"等批量操作）
- 单条 hover 应可删
- 空状态 = "没有已保存的记忆"

### Memory 开关 × 3

- 参考保存的记忆（显式 memory）
- 参考浏览器记忆（Atlas）
- 参考历史聊天记录（**这是大头**——大部分跨对话上下文从这来，不是显式 memory）

### Pulse / 录音模式

不是核心管理目标，略。

## 6. 全局页面

### 库 `/library`

- 三个 tab：**全部 / 图片 / 文件**
- 右上"搜索资料库" + "上传"按钮（上传走 Codex Chrome file chooser）
- 视图切换：列表 / 网格
- hover 一行：左侧出 checkbox（批量选）、右侧出 `...`
- 行内 `...` 菜单：**下载 / 删除（红）**

### 应用 `/apps`

应用市场页，浏览可连接 connector。不属于管理范围，主 Codex 不要替用户连接/撤销 OAuth。

### 安排 `/schedules`

ChatGPT 原生定时任务的全局列表页。空状态："启动安排的任务 — 让 ChatGPT 在未来执行操作"。创建入口推测在 message 级 ... 但实测 Instant 没看到（可能 Pro/Thinking 才有）。

## 6.5 产物下载（跟上传方向相反，走浏览器原生通道，可用）

下载走浏览器原生 download 通道。文件落到 `~/Downloads/`，主 Codex 用 shell 取最新文件或按文件名 pattern 匹配。

### 三种产物的下载路径

| 产物类型 | 入口位置 | 触发方式 | 命名 |
|---|---|---|---|
| **ChatGPT 给的下载链接**（PDF/CSV/代码文件等） | message 正文里"下载："后面的超链接（实测 Pro 生成 PDF 后会自动给） | `click` 链接 | 用户原文件名（重名加 `(N)` 后缀） |
| **ChatGPT 生成的图片** | 图片下方 ref（"分享此图片"按钮）→ 弹窗最右侧橙色"下载"按钮 | `click` 该按钮 | `ChatGPT Image YYYY年M月D日 HH_MM_SS.png` |
| **库 `/library` 里的历史文件** | hover 一行 → 右侧 `...` → "下载" | `click` "下载" | 用户/系统原文件名 |

### 屏蔽掉的旁路（**别试**）

- ❌ 取 `img.src` 后用 curl 下载。图片资源 URL 可能含 cookie/query 凭证，不要把签名 URL 带进上下文或 shell
- ❌ Message 级 `...` 菜单：只有"查看来源 / 新聊天中的分支 / 朗读"，**没有下载**
- ❌ 图片相邻的 "更多操作" / "编辑图片" / "复制回复"：都不是下载
- ❌ 右键图片 → 浏览器原生右键菜单：Codex Chrome Extension 不能跟 OS-native 菜单交互

### 主 Codex 找下载文件

下载到 `~/Downloads/` 后，主 Codex 用 shell：

```bash
# 看最新 5 个文件
/bin/ls -lat ~/Downloads/ | head -7

# 按 pattern 找
/bin/ls -t ~/Downloads/ChatGPT\ Image*.png | head -1
/bin/ls -t ~/Downloads/W7D3*.pdf | head -1
```

注意 `eza`（macOS 一些用户的 ls 替代品）不支持 `-t` 排序时间，要用 `/bin/ls` 强制系统 ls。

### 安全边界

- 单文件下载是用户级别决策——主 Codex 在点下载按钮前要明确告诉用户"准备下载到 `~/Downloads/<filename>`"，让用户口头同意
- **图片"分享此图片"弹窗内的 "复制链接" 按钮会创建公开 URL**（推测，跟对话分享对齐）——只点"下载"不会，但要小心别点错。看到下载按钮就直接点，不要先点其他社交平台按钮试探
- 下载后**不要自动 Read 或处理用户的私人文件内容**，除非用户明确要求

## 7. URL 形态 cheat sheet

| URL 模式 | 上下文 |
|---|---|
| `/c/<conv-uuid>` | 普通对话 |
| `/g/g-p-<project-uuid>/project` | 项目主页（创建后未命名/未带 slug） |
| `/g/g-p-<project-uuid>-<name-slug>/project` | 项目主页（命名后带 slug） |
| `/g/g-p-<project-uuid>/c/<conv-uuid>` | 项目内对话（DSE数学这种老项目的格式） |
| `/g/g-p-<project-uuid>-<name-slug>/c/<conv-uuid>` | 项目内对话（新项目带 slug 的完整格式） |
| `/library`、`/apps`、`/schedules` | 全局页面 |
| `#settings/<Section>` | 设置面板（各 tab 入口见本文件第 4-5 节） |

## 8. 安全总则（**主 Codex 必须遵守**）

1. **对话级"分享"打开即创建公开 URL**——没用户明确同意之前别点。一旦点了，撤销路径是 `#settings/DataControls → 管理共享链接 → 删除该行`。⚠️ **图片的"分享此图片"弹窗不一样**——打开不会自动创建（只在点"复制链接"时创建），所以为了下载图片不得不打开它是 OK 的
2. **开始群聊视同分享**——确认前要用户授权
3. **删除项目会一起删项目内所有对话**——主 Codex 在 prompt 用户前必须明示这点
4. **删除对话不自动清 Memory**——删完后提醒用户去个性化 → 记忆 [管理] 单独清
5. **个性化里"你的详情"和"记忆"含用户隐私**——绝不导出/复制到外部对话窗口/落盘到非用户授权文件
6. **任何破坏性操作（删/归档全部/全部删除/撤销分享）执行前必须用户口头确认**——不是看到红色按钮就能直接点
7. **上传**：优先使用 Codex Chrome file chooser。失败时报告页面/扩展可见错误，尤其是文件 URL 权限问题；不要改用 cookie、签名 URL 或系统拖拽旁路
8. **OAuth / connector 授权**：主 Codex 绝不替用户授权或撤销 connector（参见 [error-and-limits.md](error-and-limits.md) 第 5 节）
