# Example: 在项目里咨询 Pro（自动用项目知识库）

## 触发说法

- "在我的 DSE数学 项目里问一下..."
- "用 GI2 项目的上下文写点东西"
- "让 ChatGPT 在职业发展项目里基于知识库回答 X"
- 用户提到某个项目名 + 一个需要项目知识库参与的问题

## 意图解析

- **模型**：用户没指定就保留当前模型；Pro 配合长 PDF 知识库效果最好
- **位置**：必须进入项目主页 + 在项目里新建对话（**不能在普通 `/c/<id>` 会话里**，那拿不到项目知识库）
- **不需要 `@app`**：项目知识库会自动被引用，不需要 mention 任何 connector

## 操作步骤

1. `tabs_context_mcp` → 复用或创建 ChatGPT tab
2. **进入项目主页**——这步有坑：
   - 侧栏项目区找到目标项目（如 "DSE数学"）
   - **不要只点项目名按钮**——那只展开/折叠子项列表
   - 找 hover 时出现的 **"打开项目首页"** 按钮（ARIA label），点它
   - URL 变成 `/g/g-p-<project-uuid>/project` 且页面有项目大标题，进入成功
3. **可选：先看知识库都有啥**
   - 点 "来源" tab（URL 加 `?tab=sources`）
   - read_page 看文件列表（PDF / docx / 网址等）
   - 这一步可以省略，但能让主 Claude 在 prompt 里精确引用文件名（如 "请基于 X.pdf 和 Y.pdf 分析..."），引用越精确 ChatGPT 越容易触发知识库检索
4. 切回 "聊天" tab
5. 模型选择（如有）
6. **验证你确实在项目里**：composer placeholder 应该是 **"<项目名>中的新聊天"**（不是普通的 "有问题，尽管问"）。这是项目模式的可靠视觉信号
7. 写 prompt：
   - 如果想强制用知识库 → 在 prompt 里点名文件 "基于知识库里的 X.pdf 和 Y.pdf..."
   - 如果想看 Pro 自己选 → 让它自由发挥，问问题就行
   - **可以让 Pro 反驳错误假设**：项目知识库有时让 Pro 发现你 prompt 里的事实错误。这是项目模式的核心价值
8. 发送 → 等 3-5 秒看 URL 出现
9. **记下 URL** —— 注意是 **`/g/g-p-<project-uuid>/c/<conv-uuid>`**，不是普通 `/c/<id>`
10. **Spawn Haiku watcher**：

    项目内 + PDF 知识库的任务等待时间会很长（实测 Pro 可以跑 21+ 分钟）。建议：
    - `sleep` 间隔 90-120 秒（不要太频繁打扰）
    - 累计等待硬上限在 watcher prompt 里把 1800s 调到 1800s（30 分钟）就够，超长任务用户该手动跟进

## 异步等待 + 取回

- Watcher 完成时返回完整回答 + 项目知识库引用迹象
- 主 Claude 呈现给用户：
  - 项目名、conversation URL（含项目路径）、思考时间、watcher 累计等待
  - **项目知识库引用迹象**——是否真的引用了知识库文件（YES/NO + 文件名）
  - 完整回答（Pro 在项目里经常给非常长的结构化输出，建议落盘到 `.chatgpt-web-delegate/results/<project>-<topic>-<date>.md` 给路径而不是直接贴回主对话）

## 容易踩的坑

- **只点项目名按钮 → 没进项目主页**：那只展开子项列表，需要再点 "打开项目首页"
- **不验证 composer placeholder → 不知道自己有没有真的在项目里**：placeholder 应该是 "<项目名>中的新聊天"，不是这个就**没进项目**
- **以为项目知识库要 `@<file>` 引用**：不需要。在项目里发问就行，Pro 会自动检索
- **以为 conversation URL 还是 /c/<id>**：不是。项目内是 `/g/g-p-.../c/...`。watcher prompt 里要用完整 URL
- **Pro 在 PDF 多文件比较任务上等待超长**：21 分钟很正常。watcher 间隔不要设得太短，否则会浪费 token 反复 read_page
